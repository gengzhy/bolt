Windows/Android 全平台 QUIC 局域网极致传输优化最终执行方案
本方案旨在解决 QUIC 协议在局域网高带宽、低延迟环境下因默认参数保守、IO 模型串行导致的吞吐瓶颈。通过统一跨平台（Windows/Android/Linux）的底层网络参数、重构异步零拷贝 IO 模型，使 QUIC 传输性能无限贴近 TCP 内核物理极限（预期达到 TCP 性能的 85%~95%）。
2. 核心参数设计原则
2.1 QUIC 传输层参数 (TransportConfig)
摒弃广域网保守策略，全面解禁局域网限制：
- 窗口解禁：流接收窗口 8MB，连接接收窗口 16MB，彻底打破 64KB/256KB 默认锁死。
- MTU 探测：开启 MTU Discovery，强制跑满 1472 字节大包，消除小包头部开销。
- 拥塞控制：固定使用 CUBIC（内网高带宽下比 BBR 吞吐更稳定、延迟更低）。
- 并发控制：双向/单向流上限均设为 64，支持多文件并发。
2.2 UDP 内核缓冲参数
- 强制 4MB 缓冲区：QUIC 基于 UDP，系统默认 UDP 缓冲极小（通常几十 KB），必须在 Socket bind 前通过 socket2 强制设置为 4MB，防止内核静默丢包。
2.3 异步零拷贝 IO 模型
- 发送端：文件读取与 QUIC 发送异步解耦。使用 BytesMut 内存池化避免堆分配，使用 write_chunk 实现真正的零拷贝发送。
- 接收端：禁止逐块落盘。使用 read_chunk 接收，在内存中攒够 256KB 后再统一调用 write_all 落盘，防止磁盘 IO 回压 QUIC 接收窗口。
