# LocalTransfer 本地离线高速跨端文件传输助手
## 基于Rust统一底层全端方案（方案4）需求分析报告
文档编号：LT-RUST-REQ-20260827
适用场景：技术框架选型、项目初始化搭建、业务逻辑编码开发直接依据
排除内容：方案2对比、多套原生方案相关内容，全文仅围绕Rust底层统一架构展开

## 一、文档概述
### 1.1 项目定位
一款完全不依赖公网、无服务器中转、纯本地局域网点对点高速文件传输工具，覆盖 Windows / macOS / Linux / Android / iOS，支持手机↔手机、PC↔手机、手机↔PC双向文件/文件夹批量传输，依托Rust实现统一网络、文件、设备发现底层，各平台仅保留轻量UI交互层。

### 1.2 文档作用
1. 作为技术选型唯一标准，确定所有依赖库、编译链、跨端交互规范；
2. 作为项目目录结构、CI构建脚本、FFI接口规范搭建依据；
3. 作为业务模块编码开发说明书，定义所有交互流程、协议格式、异常规则；
4. 测试、联调、性能优化统一基准。

### 1.3 约束前置
1. 所有数据报文仅在二层局域网转发，不访问外网、不上传任何数据至云端；
2. 核心网络、文件分片、校验、设备发现逻辑仅实现一套Rust代码，三端共用二进制库；
3. UI层仅做页面渲染、系统权限申请、进度展示，禁止在UI层实现任何传输业务逻辑；
4. 兼容环境：同WiFi局域网、手机热点点对点、WiFi Direct无线直连。

## 二、功能性需求
### 2.1 设备发现模块需求（Rust底层实现）
1. mDNS组播自动广播
    - 启动后持续向 224.0.0.251:5353 UDP组播广播本机服务信息；
    - 广播数据包含：设备唯一UUID、设备类型(PC/Android/iOS)、本机局域网IPv4、QUIC监听端口、TCP备用端口、设备显示名称、系统版本标识；
    - 广播心跳周期：3s，离线设备10s未收到广播自动从列表移除。
2. mDNS监听扫描
    - 持续监听局域网组播报文，解析在线设备并维护内存设备列表；
    - 去重逻辑：基于设备UUID过滤重复设备，同一IP多设备分开展示。
3. 蓝牙BLE辅助发现（无WiFi兜底）
    - Rust底层封装BLE基础交互，两端蓝牙配对后交换对方局域网IP；
    - BLE仅用于交换IP，不承担文件传输。
4. 手动IP直连兜底功能
    - 对外FFI提供接口，支持手动输入目标IP+端口强制建立连接，绕过mDNS扫描失败场景。
5. 端口自动适配
    - 默认监听端口：8899（QUIC/TCP共用）；端口占用时自动递增切换备用端口池 8900~8950。

### 2.2 高速传输通信模块需求（Rust底层核心）
1. 双协议自适应传输（主QUIC，TCP降级兜底）
    - 优先使用QUIC协议多路流并发传输，支持多文件同时并行上传下载；
    - UDP端口被防火墙拦截时自动切换TCP长连接传输；
    - TCP优化：关闭Nagle算法、动态调整滑动窗口、4路并发流拉满带宽。
2. 长连接管理
    - 每台远端设备独立一条持久长连接，维护连接状态（空闲/传输中/断开）；
    - 内置30s心跳包，无响应自动断开并触发自动重连机制。
3. 断线断点续传
    - 传输中断时持久化分片进度本地缓存；
    - 重连成功后读取已传输分片序号，跳过已完成分片继续传输，无需重传全量文件。
4. 传输模式切换
    - 高速明文模式：内网可信环境，关闭TLS加密，最大化吞吐；
    - 安全加密模式：QUIC/TCP启用rustls TLS1.3加密，文件二进制全程加密传输。

### 2.3 私有二进制通信协议规范（统一编解码，Rust唯一实现）
所有网络数据包固定结构，解决字节流粘包、拆包问题，全端统一标准：
[4字节 大端序 数据包整体长度]
[1字节 指令类型码]
[8字节 文件总长度 u64]
[2字节 文件名称UTF8字节长度]
[N字节 文件名称]
[32字节 文件MD5校验哈希]
[剩余字节 文件分片二进制数据]

指令码定义：
0x01：握手报文，两端协商分片大小、加密模式、协议版本
0x02：文件分片发送报文
0x03：分片接收ACK确认报文
0x04：断点续传请求报文（携带已完成分片索引）
0x05：文件传输完成校验通知
0x06：主动取消当前传输任务
0x07：心跳保活报文

分片规则：
默认分片大小1MB，弱网环境自动降级256KB；
Rust底层自动自适应分片尺寸，UI层无需感知。

### 2.4 文件处理引擎需求（Rust底层零拷贝实现）
1. 本地文件读取
    - 使用 memmap2 mmap内存映射读取大文件，避免完整加载文件至堆内存，杜绝GB级文件OOM；
    - 支持单个文件、多层文件夹递归遍历，自动收集子文件列表、计算总大小、批量生成传输任务。
2. 文件写入与合并
    - 接收分片写入临时.tmp缓存文件，分片按序号有序写入；
    - 全部分片接收完成、MD5校验通过后，重命名为原始文件名；
    - 传输失败自动清理临时缓存文件，释放磁盘空间。
3. 文件完整性校验
    - 传输前本地预计算文件MD5；
    - 文件接收完成后二次校验MD5，不一致判定文件损坏，自动触发重传。
4. 本地缓存持久化
    - 断点续传进度、在线设备缓存存储至本地应用私有目录；
    - 支持清空传输记录、清除临时缓存接口。

### 2.5 任务调度与进度管理需求
1. 多任务队列
    - 支持同时发起多组设备互传任务，上传、下载任务并行调度；
    - 任务状态：待连接、传输中、已暂停、已完成、传输失败、已取消。
2. 实时进度计算
    - 实时计算单文件/总任务已传输字节、总字节、瞬时传输速率（Mbps）；
    - FFI实时推送进度数据至各端UI层渲染进度条、速度数值。
3. 任务控制接口
    - 启动传输、暂停传输、取消单文件任务、清空全部队列。

### 2.6 各端UI层标准化交互需求（仅调用Rust FFI，无业务逻辑）
#### PC端（Tauri + Vue3 + TS）
1. 首页：局域网在线设备列表展示，刷新扫描按钮；
2. 传输面板：拖拽文件/文件夹上传，接收文件列表、实时进度、传输速度；
3. 设置面板：明文/加密模式切换、自定义保存目录、手动IP连接、清空缓存；
4. 系统适配：防火墙端口检测提示、文件系统权限申请。

#### Android端（Kotlin原生）
1. 权限申请：本地网络、WiFi状态、文件存储、附近设备、前台通知权限；
2. 前台服务：后台常驻，锁屏保活网络连接，防止系统断连；
3. 文件选择：系统SAF文件管理器，支持内部存储/SD卡文件选择；
4. 传输通知栏：实时展示传输进度，支持通知栏一键取消任务。

#### iOS端（Swift UIKit）
1. 权限申请：本地网络Bonjour权限、文件沙盒访问、蓝牙权限；
2. 后台任务注册：BackgroundTask延长后台传输存活时间；
3. 文件选择：系统文件App选择本地文件，接收文件写入沙盒下载目录。

## 三、非功能性需求
### 3.1 性能指标
1. 有线千兆局域网：传输速度接近网卡满速 ≥900Mbps；
2. WiFi6同局域网：单文件峰值 ≥800Mbps，多文件并发 ≥1.1Gbps；
3. 内存占用：后台空闲CPU＜10%，传输峰值CPU＜15%，内存无持续泄漏；
4. 大文件支持：单文件支持100GB级无卡顿传输；
5. 响应速度：设备扫描刷新≤500ms，建立连接握手≤100ms。

### 3.2 稳定性需求
1. 72小时连续循环传输无崩溃、断连、文件损坏；
2. 锁屏、切换WiFi/热点场景自动重连，断点续传无数据丢失；
3. 磁盘空间不足时主动终止任务并推送异常提示至UI；
4. 网络波动、丢包场景QUIC自动恢复，无需重启任务。

### 3.3 兼容性需求
1. PC：Windows10/11、macOS 11+、Ubuntu 20.04+；
2. Android：最低Android 10（API29）；
3. iOS：最低 iOS 14；
4. 网络：2.4G/5G WiFi、手机热点、有线局域网、WiFi Direct。

### 3.4 包体积与资源需求
1. PC Tauri客户端安装包 ≤15MB；
2. Android APK安装包 ≤20MB；
3. iOS IPA安装包 ≤25MB；
4. Rust底层静态/动态库无冗余依赖，不捆绑第三方运行时。

### 3.5 安全需求
1. 明文模式仅内网使用，无任何数据对外发送；
2. 加密模式TLS1.3端到端加密，中间人无法截取文件内容；
3. 所有本地缓存文件仅应用自身可读，无全局开放权限；
4. 无埋点、无日志上传、无外网网络请求。

## 四、技术架构需求（框架搭建强制标准）
### 4.1 整体分层架构（编码分层规范，严格执行）
#### 第一层：平台UI适配层（各端独立，禁止业务逻辑）
1. PC：Tauri前端 TS/Vue，通过 invoke 调用Rust FFI函数；
2. Android：Kotlin JNI加载lt_ffi.so，调用C风格FFI接口；
3. iOS：Swift导入xcframework，调用导出C接口；
职责：页面渲染、系统权限申请、系统文件选择、进度展示、用户操作事件透传至底层。

#### 第二层：统一Rust核心业务层（唯一业务实现，全端复用）
模块化拆分独立Crate：
lt-utils：通用工具、错误码、IP、端口检测
lt-crypto：MD5、TLS1.3加密套件
lt-discovery：mDNS广播扫描、BLE辅助发现
lt-file：mmap文件分片、断点缓存、文件夹遍历
lt-transfer：QUIC/TCP引擎、协议编解码、连接池、心跳
lt-task：任务队列、进度计算、任务调度
lt-ffi：统一C风格FFI对外导出接口

统一异步运行时：Tokio，全模块异步IO，无阻塞读写。

#### 第三层：系统底层适配层（Rust跨平台兼容封装）
基于 libc、平台专属绑定封装系统能力：网卡读取、内存映射、本地存储、进程保活指令，屏蔽Windows/macOS/Android/iOS系统API差异。

### 4.2 Rust核心依赖库强制选型
tokio = { version = "1.0", features = ["full"] }
quinn
mdns-rs
bytes
memmap2
ring、rustls
cbindgen
cross
prost
tracing

### 4.3 各端项目框架搭建规范
#### PC端：Tauri v2
1. 前端框架：Vue3 + TypeScript + Vite；
2. 通信方式：Tauri Command 调用内置Rust FFI；
3. 打包输出：Windows exe、macOS dmg、Linux AppImage；
4. 权限配置：tauri.conf.json 仅开放文件读写、网络权限。

#### Android端工程
1. 构建工具：Gradle Kotlin DSL；
2. Rust集成：cross 预编译 arm64-v8a / x86_64 .so 库，放入jniLibs；
3. 交互：JNI 封装调用Rust导出C FFI函数；
4. 后台：Foreground Service 网络保活。

#### iOS端工程
1. 开发工具：Xcode 14+；
2. Rust集成：cross编译通用xcframework，导入Xcode工程；
3. 交互：Swift桥接C头文件，直接调用FFI导出函数；
4. 后台：BGTaskScheduler 后台传输任务注册。

### 4.4 FFI接口统一规范
1. 所有对外接口为扁平C风格函数，不传递复杂结构体、Rust特有类型；
2. 字符串统一使用C char*，Rust内部做安全拷贝，避免悬垂指针；
3. 进度、设备列表等批量数据采用回调函数推送至UI层；
4. 接口命名统一前缀 lt_，所有错误返回int状态码（0=成功，负数为错误码）；
5. cbindgen自动生成 .h 头文件，Android/iOS共用同一套头文件。

## 五、业务完整执行流程（编码业务逻辑开发依据）
### 流程1：程序启动初始化流程
1. 各端UI启动，初始化平台基础组件（前台服务/后台任务/窗口）；
2. UI调用 lt_init() 初始化Rust核心底层；
3. Rust初始化Tokio运行时、mDNS广播监听、QUIC/TCP服务监听、本地缓存加载；
4. Rust启动设备扫描循环，实时推送在线设备列表至UI展示；
5. UI申请系统网络、文件权限，检测防火墙端口是否放行。

### 流程2：建立设备连接流程
1. 用户UI选择目标在线设备，或手动输入IP；
2. UI调用 lt_connect_device(设备UUID/IP)；
3. Rust底层优先发起QUIC握手，失败自动降级TCP；
4. 两端执行握手报文交互，协商分片大小、加密模式、协议版本；
5. 连接成功后UI展示设备可传输状态，开放文件上传按钮。

### 流程3：文件上传发送流程
1. UI选择本地文件/文件夹，将文件路径数组传入Rust接口；
2. Rust lt-file模块递归遍历文件，计算总大小、预生成MD5、切分分片；
3. 写入断点续传缓存，创建传输任务加入任务队列；
4. 异步循环发送分片，每发送一块等待远端ACK确认；
5. 实时计算传输速度、进度，通过FFI回调推送至UI刷新；
6. 全部分片发送完成，发送MD5校验报文；
7. 收到远端校验成功指令，任务标记完成，清理临时缓存。

### 流程4：文件接收下载流程
1. 远端发送握手与文件元数据报文；
2. Rust创建本地临时.tmp文件，初始化分片接收缓冲区；
3. 持续接收分片，按序号写入临时文件，返回ACK确认；
4. 实时推送接收进度至UI；
5. 全部分片接收完毕后本地校验MD5；
    - 校验通过：重命名文件至用户指定保存目录，任务完成；
    - 校验失败：删除临时文件，推送错误回调，支持重传。

### 流程5：断线与断点续传流程
1. 网络断开、锁屏触发连接断开，Rust保存当前任务分片进度；
2. 后台自动3s间隔重连目标设备；
3. 重连成功后发送断点续传请求，携带已完成分片索引；
4. 两端跳过已传输分片，从断点位置继续传输，进度无缝衔接。

## 六、异常与错误处理需求（编码异常逻辑标准）
### 6.1 统一错误码定义（FFI对外返回标准）
0：执行成功
-1：参数非法
-2：网络端口被占用
-3：连接超时/远端设备离线
-4：文件不存在/无读取权限
-5：磁盘剩余空间不足
-6：文件MD5校验不匹配（文件损坏）
-7：mDNS扫描失败（防火墙拦截）
-8：内存映射文件失败
-9：任务已被用户取消
-10：系统后台权限不足（锁屏断网）

### 6.2 统一异常处理规则
1. Rust底层捕获所有IO、网络、文件异常，转换为标准错误码通过FFI返回UI；
2. 所有异常不直接崩溃进程，记录本地日志并推送异常回调；
3. UI层仅根据错误码展示对应中文提示弹窗，禁止UI自行处理底层异常；
4. 网络类异常自动执行重试逻辑，文件损坏异常提供“重新传输”按钮。
